# Review Process — OneRedOak 8단계 디자인 리뷰

> 출처: OneRedOak `claude-code-workflows` (3.9k★) 디자인 리뷰 프로세스 이식.
> 이 문서는 harness의 판정자(QA·Vision)가 스크린샷을 크리틱할 때 참조하는 **프로세스 앵커**다.
> 판정 원칙: 문제를 **처방이 아니라 문제·영향으로** 기술하고, **실제 실행 화면부터** 평가한다.

## 핵심 철학

### Live Environment First (실행 화면 우선)
정적 코드 분석보다 **실제 렌더된 화면(스크린샷/라이브 미리보기)** 을 먼저 평가한다.
코드가 "맞아 보여도" 렌더 결과가 깨질 수 있으므로, 판정은 항상 실물 증거에서 출발한다.
코드 헬스 점검(Phase 6)은 실행 평가가 끝난 뒤 마지막에 수행한다.

### Problems over Prescriptions (처방보다 문제)
판정자는 해결책을 지시("margin을 16px로 바꿔라")하지 않는다.
대신 **관찰된 문제와 사용자 영향**을 기술한다.

- 나쁜 예 (처방): "이 버튼 padding을 12px로 늘려라."
- 좋은 예 (문제·영향): "버튼의 터치 영역이 인접 요소와 붙어 있어 오탭 위험이 있고, 주변 요소와 간격이 불일치해 시각적 혼란을 유발한다."

처방은 구현자가 컨텍스트를 갖고 결정할 몫이다. 판정자는 **왜 문제인지**를 명확히 한다.

### Evidence + Acknowledge (증거 + 인정)
- **잘된 점을 먼저 인정**한다. (예: "상단 헤더의 타이포 위계는 명확하고 색 대비도 충분하다.")
- 모든 지적에는 **스크린샷 증거**(해당 영역·좌표·상태)를 첨부한다.
- 추측성 지적 금지 — 화면에서 확인 가능한 것만 지적한다.

## 8단계 리뷰

### Phase 0 — 준비 (Preparation)
- 리뷰 대상 화면·명세·변경 범위를 파악한다.
- 실행 환경(디바이스/뷰포트/데이터 상태)을 준비한다.
- 승인된 명세(spec)와 외부표준(WCAG/HIG/8px)을 앵커로 로드한다.

### Phase 1 — 인터랙션 & 사용자 플로우 (Interaction & Flow)
- 주요 사용자 플로우를 끝까지 따라간다 (해피패스 + 이탈 경로).
- 상태 전이를 점검: **hover / active(press) / disabled** 및 focus.
- 인터랙션 피드백(로딩·성공·실패 표시)이 존재하고 명확한지 확인.

### Phase 2 — 반응형 (Responsiveness)
- 데스크톱/태블릿/모바일 브레이크포인트에서 레이아웃 검증:
  - **1440px** (데스크톱), **768px** (태블릿), **375px** (모바일).
- **모바일은 뷰포트 축소가 아니라 실제 기기 프레임**(노치/홈 인디케이터 포함)에서 평가한다.
- 콘텐츠 리플로우, 잘림, 가로 스크롤 발생 여부 확인.

### Phase 3 — 비주얼 폴리시 (Visual Polish)
- **정렬**: 요소 정렬선 일관성 (좌/우/베이스라인).
- **간격**: 간격 리듬 일관성 (8px 그리드 준수 — `design-standards.md` 참조).
- **타이포 위계**: 제목/본문/캡션 위계가 명확한가.
- **색 일관성**: 팔레트 일관성, semantic 색 오용 없는지.

### Phase 4 — 접근성 (Accessibility, WCAG 2.1 AA)
- **키보드**: 모든 인터랙티브 요소에 키보드 도달·조작 가능.
- **포커스**: 포커스 링이 시각적으로 명확하고 순서가 논리적.
- **시맨틱**: 의미에 맞는 역할/레이블(버튼은 버튼, 헤딩 위계).
- **대비**: 텍스트/배경 대비 **4.5:1 이상** (큰 텍스트 3:1). 이 기준 미달은 접근성 Blocker 후보.

### Phase 5 — 견고성 (Robustness / Edge States)
- **빈 상태(empty)**: 데이터 0건일 때 화면이 무너지지 않고 안내가 있는가.
- **에러 상태**: 실패 시 명확한 에러 메시지·복구 경로가 있는가.
- **오버플로우**: 긴 텍스트·다국어·큰 숫자에서 잘림/깨짐이 없는가.

### Phase 6 — 코드 헬스 (Code Health)
- **디자인 토큰 사용**: 색·간격·타이포가 토큰/변수로 참조되는가.
- **매직 넘버 금지**: 하드코딩된 `16px`, `#3A3A3A` 같은 리터럴이 반복되면 지적.
- 컴포넌트 재사용·중복 제거 여부.
- (실행 화면 평가 이후 마지막에 수행 — Live Environment First 원칙.)

### Phase 7 — 콘텐츠 & 콘솔 (Content & Console)
- **콘텐츠**: 오탈자, 어색한 문구, 플레이스홀더 잔존(`Lorem ipsum`, `TODO`) 확인.
- **콘솔**: 브라우저/런타임 콘솔에 경고·에러 로그가 없는지 확인.

## 트리아지 매트릭스 (Triage Matrix)

발견 사항은 반드시 아래 4등급 중 하나로 분류한다.

| 등급 | 표기 | 의미 | 처리 시점 |
|------|------|------|-----------|
| Blocker | `[Blocker]` | 기능·접근성·데이터를 깨뜨림. 대비 4.5:1 미달, 크래시, 조작 불가 | **즉시 수정** (머지 차단) |
| High-Priority | `[High-Priority]` | 명확한 UX/비주얼 결함 | **머지 전 수정** |
| Medium-Priority | `[Medium-Priority]` | 개선이 바람직하나 차단은 아님 | **후속 작업** |
| Nitpick | `[Nitpick]` (`Nit:`) | 취향·미세 개선 제안 | 선택 — `Nit:` 접두사로 표기 |

예시:
- `[Blocker]` 본문 텍스트 대비 2.8:1로 WCAG AA 미달 — 저시력 사용자가 읽을 수 없음.
- `[High-Priority]` 저장 버튼에 disabled 상태 피드백이 없어 중복 제출 가능.
- `[Medium-Priority]` 카드 간 간격이 12px/20px로 혼재해 리듬이 깨짐.
- `Nit:` 캡션 자간이 약간 좁아 보임.

## 판정 출력 계약

각 판정(`verdict.md`)은 다음을 포함한다:
1. **잘된 점** (인정) 1~N개.
2. 트리아지 등급별 **발견 사항** — 각 항목에 문제·영향 + 스크린샷 증거.
3. 트랙 A(명세 준수) / 트랙 B(외부표준 크리틱) 요약.
4. 정지 판단: success / plateau / stuck / infra-fail.
